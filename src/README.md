# Source Code Documentation

This folder contains the TypeScript source files that provide the
functionality of the `@xpack/logger` library.

## Overview

**Build Output:** compiled by `tsc` to ES modules in the `dist/` folder  
**Module System:** ES modules, with `.js` extensions in imports  
**Runtime Dependencies:** none (`@xpack/mock-console` is used only by tests)

## Folder Structure

```text
src/
├── lib/
│   └── logger.ts   # The Logger class and its types
└── index.ts        # Public API exports
```

The ES module format comes from the `"type": "module"` setting of the
root `package.json`; the folder has no `package.json` of its own.

## Key Components

### Logger

The `Logger` class is a levelled console logger.

- Levels are ordered by `Logger.numericLevels`, from `silent` (0) to
  `all` (70). A message is output when the numeric level of the logger is
  greater than or equal to the level of the method.
- The name of the warning level is `warn`, like the `warn()` method; the
  messages of this level start with the prefix `warning: `.
- The valid level names are in `Logger.levelNames`, and
  `Logger.isLogLevel()` is a type guard for a value that comes from an
  unchecked source, like a command line option. The `level` setter throws
  a `TypeError` or a `RangeError` for an invalid level.
- `Logger.recommendedLevel` (`info`) is the level that an application
  can use when none was chosen; the library never applies it.
  `Logger.defaultLevel` is its deprecated former name.
- The logging methods are `always()`, `error()`, `output()`, `warn()`,
  `info()`, `verbose()`, `debug()`, and `trace()`. `always()` uses
  `Logger.numericLevelAlways` (-1), so it is always output; `error()` and
  `warn()` write to the standard error, the others to the standard output.
  The table of the logging methods is in the TSDoc of `Logger`.
- The `isLevel()` method and the `isErrorEnabled`, `isWarnEnabled`, ...,
  `isAllEnabled` getters test the current level; `hasLevel` tells whether
  a level was set. The previous names of the getters (`isError`, `isWarn`,
  ..., `isAll`) are deprecated, and so is `isSilent`, which is always true.
- The constructor accepts an optional object with the `level`, the
  `console`, and the `timestamp` option (see `LoggerParams`). The
  `console` option lets tests inject `@xpack/mock-console` to capture the
  output; it is required when the type of the console is not the one of
  the global `console` (see `LoggerArguments`). With `timestamp`, the
  messages of `error()`, `warn()`, `debug()`, and `trace()` start with the
  local time, and the prefix is replaced by the kind in square brackets.
- The state of the logger is private. A subclass can intercept the
  messages by overriding the protected `write()` method, the supported
  extension point; the protected members `_console`, `levelNumericValue`,
  `levelName`, and `buffer` are deprecated and will be removed in the
  next major version.

### Preliminary state

A logger created without a `level` is in a preliminary state
(`Logger.numericLevelUndefined` is `Infinity`): the messages are stored in
an internal buffer and replayed when the `level` setter is called.

### Types

- `LogLevel`: the union of the level names.
- `NumericLogLevel`: the numeric value of a level.
- `LoggerFunction`: the signature of the function that writes a message,
  passed to `write()`.
- `LoggerConsole`: the console objects accepted by the logger, any object
  with the `log()` and `error()` functions; the `Logger` class has the type
  of the console as a type parameter.
- `LoggerParams` and `LoggerArguments`: the options of the constructor,
  and the arguments of the constructor, which make the `console` required
  when the global `console` is not of the type of the logger.
- `LoggerBufferRecord`: a record of the internal buffer, exported only
  because of the deprecated protected `buffer` member.

## Coding Conventions

- Use British English in comments and documentation.
- Add TSDoc comments for all classes, methods, properties, parameters,
  and return types.
- Keep the line length at or below 80 characters.
- Follow the Prettier configuration in `maintenance/config/.prettierrc.json`.

## Development Workflow

```bash
npm run compile      # Compile TypeScript to dist/
npm run lint         # ESLint check
npm run fix          # ESLint with --fix
npm test             # Compile, type-check the tests, lint, then run
                     # the tests with coverage
```

Tests are in `tests/tap/` and run directly from TypeScript.
