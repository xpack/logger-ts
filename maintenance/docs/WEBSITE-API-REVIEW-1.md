and the decisions for the maintainer last (#20 and #19).

## Note on generated pages

All the pages under `website/docs/api/`, the files in `website/tsdoc/`, and
the navigation files are generated by `npm run generate-website-tsdoc` in
`website/`: `tsc` compiles `src/` into declarations, `api-extractor`
reads their TSDoc comments into a model, `patch-doc-model-json.sh` patches
it, `api-documenter` writes Markdown, and `tsdoc2docusaurus` converts it
into the pages. The only hand-written source is the TSDoc comments in
`src/lib/logger.ts`, so a fix is a change of a comment, followed by a
regeneration. The markers of the items are **[tsdoc]** (a comment),
**[config]** (a file in `website/config/`), **[documenter]**
(`@microsoft/api-extractor` or `@microsoft/api-documenter`),
**[converter]** (`@xpack/tsdoc2docusaurus-cli`), and **[code]** (a change of
the library), with **[internal]** or **[breaking]** from
`.github/skills/review-common.md`.

The cause of items 1 to 4 is the same: TSDoc is not Markdown. It
supports code spans, fenced code blocks, paragraphs, `{@link}`, and a few
tags; everything else is passed as text, and api-documenter escapes it.
They are separate problems with separate fixes, but they are one
decision: either write the comments in the TSDoc subset, or ask whether
the toolchain should render Markdown (a change of the converter, shared
with the other xPack sites, which is not proposed here).
