## Obtain project sources

The project is hosted on GitHub:

- https://github.com/xpack/logger-ts.git

<BranchesDetails />

To contribute **Pull Requests**, fork the project and make sure the
**Copy the master branch only** option is **disabled**, so that
the `development` branch is also copied and can be used for
contributions.

:::tip

After making changes, direct the Pull Requests to the
`development` branch.

:::

The next step would normally be to **clone the forked repository**.

However, if Pull Requests are not intended, directly clone the
`development` branch of the original repository:

```sh
mkdir -p ~/Work/xpack && \
git clone \
  --branch development \
  https://github.com/xpack/logger-ts.git \
  ~/Work/xpack/logger-ts.git
```

If the repository has already been cloned, update it with:

```sh
git -C ~/Work/xpack/logger-ts.git pull
```

<summary>Add links for development</summary>

By default, npm dependencies are installed as sub-folders of
`node_modules`, with filtered content; developer-related files are not
installed. These sub-folders are also overwritten on each `npm install`,
so any changes made there are lost.

Therefore, during development, if this project is used as a dependency
of another project, it is convenient to use the full version of the
project and make changes directly in the local development folder.

The mechanism npm uses for this is called _linking_.

The process has two steps:

1. Tell the global npm configuration where the local development
   folder is located.
2. Tell the top project to use the linked development folder
   instead of the installed read-only dependency.

The first step requires executing the `npm link` command in the
local development folder, as shown below:

```sh
npm --prefix ~/Work/xpack/logger-ts.git link
```

The result is the creation of a symbolic link in the global npm
store pointing to the local development folder.

For the second step, in the top project, instead of adding the
dependency by installing it, run the command to link it:

```sh
npm link @xpack/logger
```
